# AGENTS.md — working on Rings Turn Log

Read this before changing anything that is persisted or affects existing saves.

## LocalStorage is a public contract (critical)

The app is already released (PWA, installable, offline-first): users' games live
in `localStorage`. **Never break an existing save.** Treat the stored document as
a public API you cannot change at will.

- Current key: `rings-turn-log/v1` — `STORAGE_KEY` in `src/lib/storage.ts`.
- Legacy key, still read once and migrated automatically: `lotr-lcg-memo/v1` —
  `LEGACY_STORAGE_KEY` in `src/lib/storage.ts`.
- Stored document shape:
  ```js
  {
    state,   // { turno, fase, players: [{ id, name, threat, setup }],
             //   bookmark: { container, step } | null,
             //   quest: { willpower, threat, applied } }
    history, // [{ state, label }] undo snapshots (max HISTORY_LIMIT)
    notes,   // { "container::anchor": [{ id, text, hidden? }, ...] }
    wake,    // boolean
    rotation,// 0 | 90
    lang     // "it" | "en"
  }
  ```
- Where it lives: `src/lib/storage.ts` (`loadDocument`, `saveDocument`,
  `sanitize`, `sanitizeNotes`, `sanitizeActionLabel`), `src/lib/game.ts`
  (`initialState`, `cloneState`, `makePlayer`, `makeQuest`) and
  `src/lib/store.ts` (state mutations and persistence). Types are in
  `src/lib/types.ts`.

### Rules for any change to persisted data

1. **Keep reading the current key.** Old saves must load unchanged.
2. **New fields are optional.** Give them a default in `initialState()` and a
   fallback in `sanitize()`; never assume a field exists.
3. **Never rename, remove or change the type of a persisted field** without a
   migration that reads the old value first (for example `minaccia` → `players`
   in 1.1.0, or the legacy key rename).
4. **Do not reinterpret existing values.** If semantics change, migrate them
   explicitly.
5. **If compatibility is truly impossible**, bump the storage key (`/v2`), read
   `/v1`, migrate, and write the new key. Keep the old key readable for at least
   one release.
6. **Test with an old save.** Seed `localStorage` with a previous-shaped document
   before the app boots and check that turn, phase, players, threat, notes,
   bookmark, quest and settings are restored. See
   `src/lib/storage.test.ts` and `tests/e2e/app.spec.ts`.
7. Bumping `version.js` is unrelated to the storage format: a new app version
   must still load the saves written by previous versions.

## Other project notes

- React 19 + Vite + TypeScript + Tailwind 4 + shadcn-style primitives, no backend.
- Commands: `npm run dev`, `npm run build`, `npm run preview`,
  `npm run typecheck`, `npm test` (Vitest), `npm run test:e2e` (Playwright).
- Production output is `dist/`, deployable to Cloudflare Pages. Build command
  `npm run build`, output directory `dist`.
- PWA: service worker and precache are generated by `vite-plugin-pwa`. Bump
  `version.js` on every release that changes a precached file (`index.html`,
  `src/**`, icons, audio, manifest); the build copies the root `version.js` into
  `dist/version.js`. README/CHANGELOG are not precached.
- PWA updates: the header version is the update affordance (`useAppUpdate`,
  `UpdateVersionButton`). Keep SW registration explicit (`injectRegister: null`,
  `updateViaCache: "none"`), fetch `/version.js?ts=…` with `no-store`, and keep
  `/version.js` as `no-cache` in `public/_headers`. Never auto-reload or apply
  an update without the user's second tap.
- Releases are automated by `.github/workflows/release-tag.yml` on pushes to
  `master`: it verifies `version.js` matches `package.json`, creates the
  annotated `vX.Y.Z` tag if missing, and publishes a GitHub Release using the
  matching `CHANGELOG.md` section. Bump both versions and write that changelog
  section before merging.
- `public/` holds only the manifest, the app icons and `_headers`. App icons,
  images and audio live in `src/assets` and are imported by the bundle.
- UI texts live in `src/lib/i18n/dictionaries.ts` (`it` and `en`): keep both in
  sync, and keep the stable step keys in `src/lib/constants.ts` (notes and
  bookmarks are anchored to them).
- Icons: [Radix Icons](https://www.radix-ui.com/icons). Only the SVGs actually
  used are in `src/assets`; the full `icons/` folder is gitignored.
- Dialogs are Radix portals mounted inside `#rotator`
  (`src/components/app/PortalContainer.tsx`): keep this so pop-ups stay inside
  the rotated UI.
- The layout reacts to `narrow`, `tight-head`, `compact-height`, `very-short`
  and `tablet` classes set by `src/hooks/useViewportLayout.ts`; check pop-ups in
  landscape and with the UI rotated.
